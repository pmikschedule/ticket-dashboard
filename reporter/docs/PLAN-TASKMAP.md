# 태스크 맵 — 기획안

**상태: 구현 완료 (2026-08-13).** 아래는 승인받은 설계이고, 구현하며 바뀐 것은
9장에 적었습니다. 사용법은 [reporter/README.md](../README.md#태스크-맵--사람마다-다른-등록-기준을-맞춥니다) 를 보세요.

보고서가 매주 같은 모양으로 나오게 하려면, **누가 어떻게 태스크를 등록했든
보고 항목으로 바꾸는 규칙이 한 곳에 적혀 있어야** 합니다. 지금은 그 규칙이
사람 머릿속에 있고 매번 손으로 다시 만듭니다.

---

## 1. 문제 — 실측으로 확인한 것

desk 스냅샷 `2026-08-11` (업무 38건) 에서 실제로 나온 것들입니다.

### (1) 성격별로 쪼개 등록한 태스크

```
카보너스 관리자 서비스 분석 및 기획   Alexa  ing  types=[plan]     project=carbonus-admin
카보너스 관리자 서비스 설계          Alexa  ing  types=[design]   project=carbonus-admin
카보너스 관리자 서비스 구현          Alexa  ing  types=[feature]  project=carbonus-admin
```

한 사람이 하나의 일을 3건으로 등록했습니다. 보고서 표에서 **3행**을 먹고,
읽는 사람에게는 세 개의 안건으로 보입니다. 1page 예산이 12행인데 이런 게
서너 개면 표가 그것만으로 찹니다.

### (2) 프로젝트에 안 붙은 태스크

```
FABB 보너스 설계            Jin  done  project=None
FABB 보너스 구현            Jin  done  project=None
FABB 신청화면 개발 & …      Jin  done  project=None
PG사 화면 기획 리뷰         Alexa       project=None
PG사 화면 기획              Jacqueline  project=None
```

38건 중 **12건**이 프로젝트가 없습니다. 지금은 전부 '개별 업무' 로 표 아래에
붙는데, 실제로는 어느 프로젝트의 하위 작업인 것이 섞여 있습니다.

### (3) 같은 일의 재개·중복

```
결제 시스템 운영서버 배포         Jacqueline  done  (7/28~8/7)
결제 시스템 운영서버 배포 (재개)   Jacqueline  todo
```

### (4) 사람마다 기준이 다름

`PG사 화면 기획 리뷰`(Alexa) 와 `PG사 화면 기획`(Jacqueline) 은 담당자가 다르고
제목이 거의 같습니다. 하나로 볼지 둘로 볼지는 **코드가 정할 수 없습니다.**

## 2. 원칙

- **원본 스냅샷은 고치지 않습니다.** 맵핑은 보고 단계에서만 얹습니다.
  desk 가 원본이고, 우리 규칙은 그 위의 얇은 층입니다. 원본을 고치면 다음
  스캔이 덮어쓰고, desk 와 대조도 못 합니다.
- **맵핑은 파일에 남습니다.** 매주 같은 규칙이 자동으로 적용돼야 포맷이
  안정됩니다. 이게 이 기능의 존재 이유입니다.
- **자동 통합은 하지 않습니다.** 규칙은 제안하고 **사람이 승인**합니다.
  제목이 비슷하다는 이유로 코드가 합치면, 다른 일을 합쳐 놓고 아무도 모릅니다.
- **맵핑 안 된 태스크를 조용히 버리지 않습니다.** 미분류는 보고서에 그대로
  나가고, 건수를 UI 와 각주에 띄웁니다.
- **끊어진 참조를 숨기지 않습니다.** desk 에서 태스크가 사라지거나 id 가
  바뀌면 맵핑이 끊깁니다. UI 가 그걸 첫 화면에 보여 줍니다.

## 3. 데이터 — `taskmap.json`

규칙은 한 종류입니다. **보고 항목(entry)** 하나가 desk 태스크 1개 이상을 가집니다.

```jsonc
{
  "version": 1,
  "updatedAt": "2026-08-13",
  "entries": [
    {
      "key": "e-carbonus-admin",              // 우리가 만든 안정적인 id
      "title": "카보너스 관리자시스템 구축",      // 보고서 표기명 (없으면 첫 멤버 제목)
      "project": "carbonus-admin",            // 재배정. null 이면 독립 항목
      "members": [                            // desk work.id
        "w-carbonus-admin-plan",
        "w-carbonus-admin-design",
        "w-carbonus-admin-impl"
      ],
      "note": "분석·설계·구현을 한 안건으로 봅니다",  // 보고서 '주요 진행 내용'
      "hidden": false
    }
  ]
}
```

| 하고 싶은 것 | 쓰는 법 |
|---|---|
| 통합 | `members` 에 여러 개 |
| 프로젝트 재배정 | `members` 1개 + `project` 지정 |
| 명칭 변경 | `members` 1개 + `title` 지정 |
| 제외 | `hidden: true` (각주에 건수 표기) |

**한 태스크는 최대 한 entry 에만 속합니다.** 중복은 저장 시 거부합니다 —
두 항목에 걸치면 건수가 두 번 세어집니다.

### 저장 위치가 결정 사항입니다

`reporter/data/` 는 `.gitignore` 에 있습니다 (스냅샷에 업무 내용이 그대로 들어
있어서 일부러 뺐습니다). 그런데 `taskmap.json` 은 **사람이 만든 자산**이라
잃으면 몇 시간의 분류 작업이 통째로 날아갑니다. 4장 미결 질문 참조.

## 4. 적용 — 어디에 끼워 넣는가

```
스냅샷 ──▶ [ taskmap 적용 ] ──▶ 기존 집계(weekly/monthly/list) ──▶ 산출물
             src/taskmap.ts        weekly.ts · aggregate.ts
             순수 함수
```

`applyTaskMap(state, map)` 이 `DeskState` 를 받아 **보고용 DeskState** 를 돌려줍니다.
아래 계층(주간·월간·목록)은 맵의 존재를 몰라도 됩니다.

### 통합 항목의 파생값 규칙

지어내지 않으려면 규칙이 명시돼야 합니다.

| 값 | 규칙 |
|---|---|
| 상태 | 하나라도 지연 → **지연** · 전부 완료 → **완료** · 하나라도 진행중 → **진행중** · 그 외 대기 |
| 금주 완료 | **구성원 전부가 done 이 된 주**에만 완료로 셉니다 |
| 진척율 | 완료 구성원 ÷ 전체 구성원 (`구성 2/3` 을 함께 표기) |
| 일정 | 시작 = 최소 시작일, 마감 = **미완료 구성원 중 최소 마감일** (9장 참조) |
| 담당자 | 한 명이면 이름, 여럿이면 `Alexa 외 1` |
| 진행 내용 | entry 의 `note`. 없으면 구성원 detail 중 첫 번째 |
| 유형 | 구성원 types 합집합 (`기획·설계·기능`) |

3건 중 1건만 끝났는데 '완료' 로 뜨면 거짓 보고입니다. 그래서 **전부 done 일
때만** 완료이고, 그 전까지는 진행중 + 진척율이 오릅니다.

> 이 진척율은 **프로젝트 마일스톤 진척율과 다른 값**입니다. 같은 표에 두 숫자가
> 나오므로 통합 항목 쪽에는 `구성 2/3` 을 붙여 근거를 드러냅니다.

## 5. UI

### 형태

**로컬 웹 UI** 를 새로 만듭니다. `npm run ui` → `http://127.0.0.1:4173`.

- Node 내장 `http` + 단일 HTML/JS. **의존성 0 추가**, 빌드 없음.
- `127.0.0.1` 에만 바인딩. 인증 없음 — 이 Mac 안에서만 도는 도구입니다.
- 저장은 임시 파일에 쓰고 rename (쓰는 중에 죽어도 기존 파일이 안 깨집니다).

> 기존 `web/` 대시보드에 붙이지 않는 이유: 그쪽은 Supabase(티켓) 화면이고,
> desk 스냅샷은 이 Mac 로컬에만 있습니다. 데이터가 있는 곳에 화면을 둡니다.

## 6. 자동 추천 (제안만, 적용은 사람이)

| 규칙 | 근거 |
|---|---|
| 같은 프로젝트 + 제목 접두어 동일 + types 다름 | 카보너스 관리자 3건이 정확히 이 모양 |
| 프로젝트 없음 + 제목 접두어가 다른 프로젝트 태스크와 동일 | FABB · PG사 화면 |
| 제목이 `(재개)` `(2차)` 등으로 끝나고 접두어가 같음 | 결제 시스템 운영서버 배포 |

제목 접두어는 `분석·기획·설계·구현·개발·배포·검증·점검·테스트` 앞부분으로 자릅니다.
실측에서 이 규칙만으로 4묶음이 잡혔습니다.

**추천을 적용하면 그 순간 `taskmap.json` 에 박히고, 다음 주부터는 추천이 아니라
규칙입니다.** 그래서 추천은 절대 자동 적용하지 않습니다.

## 7. 안정성

### id 가 바뀌면

`work.id` 는 `w-carbonus-admin-plan` 같은 **사람이 지은 슬러그**입니다. desk 에서
누가 바꾸면 맵핑이 끊깁니다. 그때는

- 끊어진 멤버는 entry 에서 자동 제거하지 **않습니다** (조용히 사라지면 모릅니다)
- UI 첫 줄에 `끊어진 참조 N건` 을 띄우고, 그 자리에서 다시 붙이거나 지웁니다
- 보고서 각주에도 `맵핑 끊김 N건` 을 적습니다

### 회귀 방지

- `taskmap.ts` 는 순수 함수 → 기존처럼 단위 테스트로 규칙을 못박습니다
- 저장 시 검증: 중복 멤버 · 없는 프로젝트 키 · 빈 entry → 거부하고 이유를 표시
- 스키마에 `version` 을 둡니다. 규칙이 바뀌면 마이그레이션 지점이 생깁니다

## 8. 단계와 규모

| 단계 | 내용 | 규모 |
|---|---|---|
| 1 | `taskmap.ts` 스키마·적용·검증 + 테스트 | 0.5일 |
| 2 | weekly·monthly·list 파이프라인 연결, 각주(미분류·제외·끊김) | 0.5일 |
| 3 | UI 서버 + 화면 (목록·묶기·분리·재배정·명칭·예산 게이지) | 1일 |
| 4 | 추천 규칙 + 보고서 미리보기 버튼 | 0.5일 |

1·2 단계만 해도 손으로 `taskmap.json` 을 적어 쓸 수 있습니다. UI 없이 쓰는
상태가 중간에 한 번 생기므로, 거기서 규칙이 맞는지 먼저 확인할 수 있습니다.

## 9. 구현하며 바뀐 것

### (1) 통합 항목의 마감일 — '최대' 에서 '미완료 중 최소' 로

기획안의 두 규칙이 충돌했습니다. `마감 = 최대 마감일` 과 `하나라도 지연이면 지연`
을 같이 둘 수 없습니다 — 지연은 마감일로 판정하기 때문입니다.

실제로 카보너스 3건을 묶어 돌려 보니 8/4 에 지난 마감이 8/20 마감인 '구현' 에
가려져 **지연 3건이 2건으로 줄었습니다.** 통합은 표를 줄이려고 하는 것이지 늦은
일을 감추려는 게 아니므로, **아직 안 끝난 구성원 중 가장 이른 마감일**을 씁니다.
남은 마감 중 가장 이른 날은 '다음에 무엇이 걸려 있는가' 이기도 해서 주간 보고에
더 맞습니다. 전부 끝났으면 마지막 마감일을 씁니다.

### (2) 예산 게이지에 미리보기 엔드포인트가 필요했습니다

처음에는 저장할 때만 예산을 다시 계산했는데, 그러면 **편집하는 동안 게이지가 안
움직입니다.** 게이지는 '지금 고치는 중인 구성이 한 장에 들어가는가' 를 보라고
만든 것이라 쓸모가 절반이 됩니다. `POST /api/preview` 를 두고 저장하지 않은 맵으로
같은 계산을 돌립니다 (파일은 안 건드립니다).

### (3) '제외' 를 넣었습니다

답을 못 받아 **넣되 각주에 건수를 반드시 적는** 쪽으로 했습니다. 빼는 것은
나중에 쉽지만 숨겨진 채로 몇 주 나가면 되돌리기 어렵습니다.

### (4) 세 산출물 모두에 적용합니다

주간만 적용하면 같은 주의 주간·월간·목록이 서로 다른 항목 구성을 보여 주고,
어느 쪽이 맞는지 아무도 모르게 됩니다. 주간 diff 는 **기준 스냅샷에도 같은 맵**을
적용합니다 — 한쪽만 적용하면 통합 항목이 지난주엔 없던 것으로 보여 전부
'금주 신규' 가 됩니다.

## 11. 처음 검토 때 물었던 것 (답변 반영됨)

### (1) 수작업 가공본이 첨부되지 않았습니다

"내가 수작업으로 다음과 같이 가공했는데" 라고 하셨는데 파일이나 내용이 오지
않았습니다. **그 결과물이 이 기능의 목표 포맷**입니다. 보내 주시면 위 규칙을
거기에 맞추겠습니다 — 특히 통합 항목의 이름 짓는 방식과 진척율 표기.

### (2) `taskmap.json` 을 어디에 둘까요

`data/` 는 gitignore 라 백업이 안 됩니다. 세 선택지:

| 안 | 장점 | 단점 |
|---|---|---|
| `data/taskmap.json` (현행 규칙 유지) | 업무 내용이 저장소에 안 올라감 | **잃으면 복구 불가** |
| `config/taskmap.json` (git 에 커밋) | 이력·복구 가능 | 태스크 제목이 저장소에 남음 |
| `data/` + `npm run ui` 가 자동 백업 사본 유지 | 절충 | 사본 관리가 또 하나 늘어남 |

### (3) '제외(hidden)' 를 넣을까요

보고서에서 빼는 기능은 편하지만 **한 일을 안 한 것처럼 만들 수 있습니다.**
각주에 건수를 적는 것으로 충분한지, 아니면 아예 빼는 게 나을지 정해 주세요.

### (4) 통합 항목의 진척율

`구성 2/3 = 67%` 로 낼지, 아니면 통합 항목은 진척율을 비우고 상태만 보여줄지.
프로젝트 마일스톤 진척율과 같은 표에 나오므로 헷갈릴 여지가 있습니다.
