# 보고서 통합 — 기획안

**상태: 승인됨 (2026-08-13). 1~3단계 완료, 4단계 진행 예정.**

주간·월간 보고서를 이슈트래커(`web/`) 안에서 만들 수 있게 합니다. 지금은 태스크
맵과 보고서 생성이 **이 Mac 의 로컬 도구**(`reporter/`)에만 있어서, 관리자가
분류한 결과를 팀이 볼 수 없고 보고서도 그 Mac 에서만 나옵니다.

---

## 1. 지금의 구조와 막히는 지점

```
desk.saebom.me ──(Chrome 쿠키)──▶ reporter/ (이 Mac)
                                    ├ data/snapshots/*.json   ← 로컬 파일
                                    ├ config/taskmap.json     ← 로컬 파일
                                    └ out/*.pptx              ← 로컬 파일

이슈트래커 web/ ──▶ Supabase (티켓)     ← desk 데이터를 전혀 모름
  https://pmikschedule.github.io/ticket-dashboard/
```

**이슈트래커는 GitHub Pages 정적 사이트입니다.** 서버가 없고 Supabase 만 봅니다.
그래서 로컬 파일을 읽을 수 없고, `http://127.0.0.1` 호출도 https 페이지에서
막힙니다. 통합하려면 **데이터가 Supabase 에 있어야** 합니다.

한편 desk 인증은 Chrome 쿠키라 **수집은 이 Mac 을 벗어날 수 없습니다.**
(`reporter/README.md` — GitHub Actions 로 못 옮기는 이유)

## 2. 가는 방향

```
desk ──(쿠키)──▶ reporter (이 Mac, 주 2회)
                   └ scan → 스냅샷 → **업로드**
                                        │
                                        ▼
                                   Supabase
                              desk_snapshots · task_map
                                        │
                                        ▼
                          이슈트래커 web/ (모두, 배포판)
                            [태스크맵] 메뉴 — 분류·통합·제외
                            [주간보고서 생성] → pptx 다운로드
```

**reporter 는 수집기로 좁아지고, 보고서·태스크맵은 web/ 이 갖습니다.**

이렇게 나누는 이유는 **로직을 두 벌 두지 않기 위해서**입니다. 보고서 생성을
양쪽에 두면 집계 규칙이 갈라지고, 어느 쪽 숫자가 맞는지 아무도 모르게 됩니다.
이 저장소는 이미 코드값을 세 곳에 두는 부담을 지고 있습니다 (`CLAUDE.md`) —
거기에 집계 규칙까지 얹지 않습니다.

> **`CLAUDE.md` 의 "reporter 는 읽기 전용 소비자" 규칙이 바뀝니다.**
> 이제 스냅샷을 Supabase 에 씁니다. 규칙 문서에 이유와 함께 고쳐 적습니다.

## 3. 데이터 — Supabase 표 두 개

```sql
-- desk 스냅샷. state 는 원본 JSON 을 통째로 (가공하면 되돌릴 수 없습니다)
create table desk_snapshots (
  day          date primary key,          -- 스캔 날짜. 하루 한 개
  scanned_at   timestamptz not null,
  source_at    timestamptz,               -- desk 의 updatedAt
  state        jsonb not null,
  counts       jsonb not null             -- work/projects/decisions 개수
);

-- 태스크 맵. 한 행이 곧 규칙 전체 (지금 config/taskmap.json 과 같은 모양)
create table task_map (
  id           int primary key default 1 check (id = 1),
  version      int not null,
  entries      jsonb not null,
  updated_at   timestamptz not null default now(),
  updated_by   uuid references users(id)
);
```

- **스냅샷은 읽기 전원, 쓰기는 관리자.** 업무 내용이라 팀 밖으로 나가면 안 되고,
  RLS 는 `is_member()` / `is_admin()` 로 지금 표들과 같은 방식을 씁니다.
- **태스크 맵은 한 행짜리입니다.** 지금 파일 한 개인 것과 같습니다. 동시 편집은
  `updated_at` 을 조건으로 건 낙관적 잠금으로 막습니다 — 두 사람이 같이 고치면
  나중 사람이 덮어쓰는 게 아니라 거절당하고 다시 읽습니다.
- 스냅샷 보존: 주 2회 × 1년 ≈ 100행. 지울 이유가 없습니다.

|---|---|---|
| ~~1~~ | ~~마일스톤 장 추가~~ | **완료** — 주간 pptx 2장째 |

`web/src/lib/report/` 로 **옮겨 갑니다.** 복사가 아니라 이동이고, reporter 는
그것을 상대경로로 가져다 씁니다. 두 벌이 되는 순간 이 계획의 목적이 사라집니다.

## 5. 1단계 — 마일스톤 장

desk `Weekly Report` 의 `1 프로젝트 진행 · 마일스톤` 을 슬라이드로 옮깁니다.
**일정표가 아니라 "각 프로젝트가 지금 어디까지 왔는가" 를 눈으로 보는 장입니다.**

```
프로젝트 진행                                       2026-08-13 기준

글로벌 BRS — 홍콩        4/9  ✓설계 ─ ✓구현 ─ ✓인프라 ─ [구현~7/29] ─ 배포 ─ 테스트   목표 8/31
카보너스 신청시스템 개선    5/8  ✓… ─ [구현] ─ 테스트 ─ 배포                          목표 —
결제 시스템 구축 [보류]    8/9  ✓… ─ [배포]                                        목표 8/7
```

| 무엇 | 어디서 |
|---|---|
| 프로젝트명·마일스톤 이름·완료여부·`4/9` | `project.milestones` (있는 그대로) |
| `보류` 배지 | `project.hold` (있는 그대로) |
| 목표일 | `project.due`. 없으면 `—` (오늘로 채우지 않습니다) |
| 현재 칩의 날짜 `~7/29` | **파생** — 그 프로젝트의 미완료 업무 중 가장 이른 마감일 |

**칩 날짜만 파생값입니다.** desk 는 `/api/state` 한 곳만 쓰고 그 응답에 마일스톤
날짜가 없습니다(실측 확인). 미완료 업무의 최소 마감일로 계산하면 desk 화면과
값이 일치했습니다 — BRS 7/29, 카보너스 관리자 8/20, Mobile App 8/11 세 건.
**파생값임을 각주에 밝힙니다.** 나중에 desk 가 필드를 열면 그때 바꿉니다.

### 지면이 모자랄 때

레일에 쓸 수 있는 폭은 8.4인치입니다. 마일스톤이 9개면 이름을 다 펴는 데
9인치가 넘습니다. 순서대로 줄입니다.

1. 글자를 7.0 → 6.0pt 까지 줄인다
2. 그래도 넘치면 **완료된 앞쪽을 `✓4` 로 접는다** — 어디까지 왔는지는 남고,
   지나온 단계의 이름만 사라집니다
3. 접은 사실을 각주에 적는다

현재 칩(첫 미완료)은 **절대 접지 않습니다.** 그게 이 장의 본문입니다.

## 6. 정하고 넘어가는 것

- **주간 표의 칩은 5종을 유지합니다** (지연·완료·착수·신규·진행중). 상태 축은
  셋(완료·진행중·지연)이고 착수·신규는 *이번 주에 시작/생성됐다* 는 변화
  표시입니다. 성격이 다르므로 같은 축으로 접지 않습니다.
- **보류는 표에서 빼고 3장 이슈로** 올립니다 (이미 적용). 마일스톤 장에서는
  프로젝트 배지로 남습니다.
- **주간 구간은 화~월**, 월간은 1일~말일 (이미 적용).
