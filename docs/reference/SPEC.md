# TaskBoard Lite — 경량 확정판 개발 기획서

> 작성일: 2026-08-04 | 사용 인원 8명 | 실작업 1~1.5일 (Claude Code 기준)
> **설계 제약: 업무 1건 등록 30초 이내**

---

## 1. 무엇을 만드는가

**8명이 각자 업무를 등록하고 진척을 갱신하면, 주간보고서와 진척 리포트가 엑셀로 떨어지는 웹앱.**

임원에게는 계정을 주지 않고 **엑셀 파일을 첨부해 보고**합니다. 이 결정으로 권한 체계·임원 대시보드·알림 발송·승인 워크플로우가 전부 불필요해졌습니다.

---

## 2. 범위 확정

| 만드는 것 | 만들지 않는 것 |
|---|---|
| 업무 등록 (2레벨 카테고리) | 프로젝트/태스크 2단 구조 → **업무 1단으로 통합** |
| 체크포인트 기반 진척률 | 공수·원가·중요도 |
| 지연 신호등 (🟢🟡🔴) | 메신저/메일 자동 알림 → 화면 표시로 대체 |
| 이슈 등록 | 이슈 결재·에스컬레이션 |
| 주간보고 자동 초안 + 제출 | 성과·역량목표 연계 모듈 |
| **엑셀 리포트 출력** | 임원 계정·임원 대시보드 |
| 팀 현황 조회 | 간트 차트 (필요 시 나중에) |

---

## 3. 아키텍처

```
[브라우저] ─┬─> GitHub Pages  : React 정적 파일
            └─> Supabase(서울) : Postgres + 아이디/비밀번호 로그인
```

8명이어도 팀장이 팀원 현황을 봐야 하므로 공유 저장소는 필요합니다. 서버는 두지 않습니다.

- 권한: `is_admin` 불리언 1개 (팀장·개발자만 true)
- RLS: 읽기·쓰기는 로그인 사용자 전원, **삭제만 admin**
- 카테고리·체크포인트 템플릿: DB가 아닌 **코드 상수**

---

## 3.5 사용자 관리 (계정 연동 없음)

**사내 계정 연동(SSO)·메일 발송·회원가입 기능을 만들지 않습니다.** 팀장이 8명을 직접 등록하고 아이디·비밀번호를 전달하는 방식입니다.

### 3.5.1 확정 방식

| 항목 | 내용 |
|---|---|
| 로그인 | 아이디 + 비밀번호 (Supabase Auth) |
| 아이디 형식 | `hong@team.local` — 실제 메일 주소일 필요 없음 |
| 계정 생성 | 팀장이 Supabase 대시보드 > Authentication > Users 에서 직접 추가 (8명, 1회 5분) |
| 이메일 확인 | **OFF** (`Confirm email` 비활성) — 메일 발송 없음 |
| 셀프 가입 | **OFF** (`Enable signup` 비활성) — 등록된 8명만 접속 |
| 최초 로그인 | 앱에서 이름·파트 입력 → `profiles` 행 생성 |
| 비밀번호 변경 | 프로필 메뉴에서 본인이 변경 |
| 퇴사·인사이동 | 팀장이 대시보드에서 계정 삭제 또는 비활성 |

**만들지 않는 화면**: 회원가입, 비밀번호 찾기, 이메일 인증, 초대 발송

### 3.5.2 로그인을 완전히 없애지 않는 이유

"이름만 선택하고 들어가기"가 가장 단순하지만 권하지 않습니다.

GitHub Pages URL은 **인터넷 전체에 공개**됩니다. 로그인이 없으면 URL을 아는 누구나 팀의 업무명·이슈 내용·담당자를 열람하고 수정할 수 있고, Supabase RLS도 사용자를 구분할 수 없어 무력화됩니다. 저장소를 Private으로 바꿔도 Pages 주소 자체는 공개이므로 해결되지 않습니다.

아이디·비밀번호 로그인은 **최초 1회 5초**이고 브라우저가 기억하므로, 이후 접속에서는 사실상 로그인 화면을 보지 않습니다. 이 정도 비용으로 위 위험이 사라집니다.

> 만약 저장되는 내용이 외부에 노출돼도 무방한 수준이라고 판단하신다면 로그인을 빼는 것도 가능합니다. 다만 그 판단은 이슈 내용에 무엇이 적히는지를 보고 결정하셔야 합니다.

## 4. 데이터 모델 (5개 테이블)

```sql
create table profiles (
  id uuid primary key references auth.users on delete cascade,
  name text not null,
  part text,
  is_admin boolean default false,
  last_cat_l1 text,                  -- 최근 사용 카테고리 (등록 속도용)
  last_cat_l2 text
);

create table tasks (
  id serial primary key,
  name text not null,
  cat_l1 text not null,
  cat_l2 text not null,
  assignee_id uuid references profiles(id) not null,
  start_date date not null,
  due_date date not null,
  deliverable text not null,         -- 템플릿에서 자동 채움
  deliverable_link text,             -- 완료 시 증빙
  status text default 'doing',       -- doing | done | hold
  due_change_count int default 0,
  due_change_reason text,
  created_at timestamptz default now()
);

create table checkpoints (
  id serial primary key,
  task_id int references tasks(id) on delete cascade,
  name text not null,
  is_done boolean default false,
  done_at timestamptz,
  sort_order int default 0
);

create table issues (
  id serial primary key,
  task_id int references tasks(id) on delete cascade,
  content text not null,
  type text not null,                -- 기술 | 자원 | 대외협의 | 요건변경 | 기타
  impact_days int default 0,
  status text default 'new',         -- new | working | resolved
  created_at timestamptz default now(),
  resolved_at timestamptz
);

create table weekly_reports (
  id serial primary key,
  user_id uuid references profiles(id),
  year_week text not null,           -- '2026-W32'
  comment text,
  submitted_at timestamptz,
  unique (user_id, year_week)
);
```

**RLS는 5개 테이블 모두 동일 패턴**
```sql
alter table tasks enable row level security;
create policy read_all   on tasks for select using (auth.uid() is not null);
create policy write_all  on tasks for insert with check (auth.uid() is not null);
create policy update_all on tasks for update using (auth.uid() is not null);
create policy del_admin  on tasks for delete using (
  exists (select 1 from profiles where id = auth.uid() and is_admin)
);
```

> 8명은 서로 신뢰하는 동료이므로 남의 업무 수정을 허용합니다. 팀장이 팀원 마감일을 직접 조정하는 상황이 실제로 더 자주 발생합니다.

## 6. 진척률·신호등

```
실적진척률 = 완료 체크포인트 수 / 전체 체크포인트 수 × 100
계획진척률 = (오늘 - 시작일) / (마감일 - 시작일) × 100
편차(SV)  = 실적 - 계획

🟢 정상  SV ≥ -5%p
🟡 주의  -20%p ≤ SV < -5%p
🔴 위험  SV < -20%p  또는  마감일 초과 & 미완료
```

화면 배지로만 표시하고 별도 알림은 발송하지 않습니다. 8명이면 주간회의에서 🔴 목록만 보면 충분합니다.

**저장 차단 규칙 (2개만 유지)**
1. 마감일 없이 저장 불가
2. 체크포인트 2개 미만이면 저장 불가 (템플릿이 자동 충족하므로 실제 마찰은 없음)

**마감일 수정 시**에만 사유 입력을 강제하고 `due_change_count`를 올립니다. 등록 시점에는 어떤 추가 입력도 요구하지 않습니다.

## 7. 업무 등록 30초 설계

### 7.1 시간 예산

| 동작 | 목표 시간 |
|---|---|
| 등록 폼 열기 (`N` 키 또는 버튼) | 1초 |
| 업무명 타이핑 | 10초 |
| 카테고리 칩 1회 탭 (최근 사용 상단) | 3초 |
| 마감일 칩 1회 탭 | 2초 |
| 자동 생성된 체크포인트 눈으로 확인 | 5초 |
| 저장 (`Ctrl+Enter`) | 1초 |
| **합계** | **22초** (여유 8초) |

카테고리를 새로 찾거나 체크포인트를 1개 지우는 경우까지 포함해도 30초 안에 들어옵니다.

### 7.2 설계 원칙

1. **입력 필드는 3개만 보인다** — 업무명 / 카테고리 / 마감일
2. **나머지는 자동으로 채우고 접어둔다** — 펼치지 않아도 저장 가능
3. **타이핑보다 탭(tap)** — 날짜 선택기와 드롭다운을 여는 동작이 가장 오래 걸림. 칩 버튼으로 대체
4. **마우스 없이 완결** — Tab 이동, `Ctrl+Enter` 저장
5. **어제 한 일은 오늘도 한다** — 최근 사용 카테고리·복제 등록으로 반복 입력 제거

### 7.3 자동 채움 규칙

| 필드 | 기본값 | 화면 노출 |
|---|---|---|
| 담당자 | 로그인 사용자 | **접힘** (남의 업무 등록은 드묾) |
| 시작일 | 오늘 | **접힘** |
| 카테고리 | 최근 사용 조합 (`profiles.last_cat_*`) | 칩으로 노출 |
| 마감일 | 이번 주 금요일 | 칩으로 노출 |
| 체크포인트 | 중분류 템플릿 | 자동 표시 (수정 가능) |
| 산출물 | 템플릿 마지막 항목 | **접힘** |
| 상태 | `doing` | 미노출 |

> 중요도(상/중/하) 필드는 **삭제했습니다.** 8명 규모에서 우선순위는 마감일이 결정하며, 중요도 입력은 시간만 쓰고 실제 의사결정에 쓰이지 않습니다.

### 7.4 등록 폼 구성

```
┌─ 새 업무 ───────────────────────────────── Esc ─┐
│                                                 │
│  [ 정산모듈 상세설계________________________ ]  │  ← 자동 포커스
│                                                 │
│  카테고리   ● 프로젝트>설계   ○ 개발>기능개선   │  ← 최근 사용 3개
│             ○ 운영>정기점검   [ 전체 ▾ ]        │
│                                                 │
│  마감일     ● 이번주 금(8/7)  ○ 다음주 금(8/14) │
│             ○ 이달 말(8/31)   [ 직접 📅 ]       │
│                                                 │
│  체크포인트 (자동)                              │
│    ☐ 설계 초안        ☐ 리뷰                    │
│    ☐ 설계서 확정                          [ + ] │
│                                                 │
│  ▸ 담당자·시작일·산출물 변경                    │  ← 접힘
│                                                 │
│           [ 저장 후 계속 ]    [ 저장 ⏎ ]        │
└─────────────────────────────────────────────────┘
```

### 7.5 단축키

| 키 | 동작 |
|---|---|
| `N` | 새 업무 등록 폼 열기 (목록 화면 어디서든) |
| `Tab` / `Shift+Tab` | 필드 이동 |
| `1`~`4` | 카테고리·마감일 칩 선택 (포커스 위치 기준) |
| `Ctrl+Enter` | 저장 후 폼 유지 (연속 등록) |
| `Enter` | 저장 후 닫기 |
| `Esc` | 취소 |

### 7.6 반복 입력 제거 장치

| 장치 | 효과 |
|---|---|
| **복제 등록** — 기존 업무 우측 `⧉` 클릭 시 이름·카테고리·체크포인트 그대로, 날짜만 다음 주기로 | 정기점검 등 반복 업무 **5초** |
| **연속 등록 모드** — `저장 후 계속` 사용 시 카테고리·마감일 유지, 업무명만 비움 | 월요일 주간계획 5건 등록 **1분** |
| **최근 카테고리 기억** — 저장 시 `profiles.last_cat_*` 갱신 | 다음 등록 시 카테고리 선택 0초 |

### 7.7 검증 방법

개발 완료 후 팀원 3명에게 **실제 업무 1건씩 등록시키고 초시계로 측정**합니다. 3명 평균이 30초를 넘으면 필드를 더 줄입니다. 다음 순서로 덜어냅니다.

1. 체크포인트 확인 단계 생략 (자동 생성분 무조건 수용, 상세에서만 수정)
2. 카테고리 대분류 5개 → 3개 축소
3. 업무명 입력만으로 저장 가능하게 하고 나머지 전부 기본값

| `#/team` | **팀 현황** | 전체 업무 표, 필터(담당자·카테고리·신호), 🔴 상단 고정 |
| `#/weekly` | **주간보고** | 내 보고 작성(자동 초안 + 이슈·코멘트) / 팀 통합본 탭 |
| `#/report` | **리포트** | 조건 선택 → 미리보기 → **엑셀 다운로드** |

모바일은 반응형으로 `#/` 와 `#/weekly` 만 되면 충분합니다.

## 9. 엑셀 리포트 사양

SheetJS(`xlsx`)로 **브라우저에서 직접 생성**합니다. 서버 불필요.

**조건**: 기간(주간/월간/직접) · 담당자(전체/개인) · 신호(전체/🔴만)
**파일명**: `팀작업현황_2026-W32.xlsx`

**시트 1 — 업무현황**
`대분류 | 중분류 | 업무명 | 담당자 | 시작일 | 마감일 | 산출물 | 실적% | 계획% | 편차 | 신호 | 상태 | 마감변경횟수`

**시트 2 — 주간보고**
`주차 | 담당자 | 금주 완료 | 진행 중 | 차주 계획 | 이슈 | 코멘트`

**시트 3 — 이슈**
`이슈 | 연관 업무 | 유형 | 일정영향(일) | 상태 | 등록일 | 경과일`

**시트 4 — 요약 (임원 보고용)**
`담당자 | 전체 | 완료 | 진행 | 지연 | 완료율 | 마감준수율 | 평균 마감변경` + 팀 합계 행

**서식**
- 1행 헤더 고정(`freeze A2`) + 자동 필터
- 신호 열 배경색: 🟢 `C6EFCE` / 🟡 `FFEB9C` / 🔴 `FFC7CE`
- 열 너비 자동 조정, 날짜는 `YYYY-MM-DD`

> **월간 임원 보고**: `#/report`에서 월간 선택 → 다운로드 → 메일 첨부. 임원 계정 불필요.

## 11. Claude Code 실행 계획 (6단계)

**사전 준비**
1. GitHub 저장소 `taskboard-lite` 생성
2. Supabase 프로젝트 생성 (리전 **Seoul**)
3. Supabase > Authentication > Providers > Email 에서 **Confirm email OFF**, **Enable signup OFF**
4. Authentication > Users 에서 팀원 8명 계정 생성 (`hong@team.local` 형식 + 초기 비밀번호)
5. clone 후 해당 디렉토리에서 `claude` 실행

**Step 1 — 초기화**
```
Vite + React + TypeScript + Tailwind + React Router + TanStack Query +
Supabase JS + SheetJS(xlsx) 로 프로젝트를 초기화해줘.
- vite.config.ts 의 base 는 '/taskboard-lite/'
- 라우터는 반드시 HashRouter
- .env.example 생성, .env 는 .gitignore
```

**Step 2 — DB + 데이터 계층**
```
docs/SPEC.md 4장의 SQL을 supabase/schema.sql 로 저장하고 RLS 정책까지 완성해줘.
그리고 src/lib/supabase.ts 와 src/lib/api.ts 를 작성해줘.
컴포넌트는 supabase 클라이언트를 직접 import 하지 말고 반드시 api.ts 만 경유하게 해줘.
```
→ 생성된 SQL을 Supabase SQL Editor에 실행

**Step 3 — 진척 로직 + 로그인**
```
src/lib/progress.ts 를 순수 함수로 작성해줘:
calcActualPct / calcPlanPct / getSignal. vitest 단위 테스트 포함.
src/lib/categories.ts 에 SPEC.md 5장의 TEMPLATES 상수를 그대로 작성해줘.
이어서 로그인을 구현해줘. Supabase Auth 아이디(이메일 형식)+비밀번호 방식이고,
회원가입·비밀번호 찾기·이메일 인증 화면은 만들지 마. 계정은 관리자가 대시보드에서 미리 생성해.
- 로그인 화면은 아이디, 비밀번호, 로그인 버튼만
- 최초 로그인 시 profiles 행이 없으면 이름·파트 입력 화면으로 유도
- 프로필 메뉴에 비밀번호 변경 기능 추가
- Layout 사이드바, 라우트 가드 포함
```

**Step 4 — 30초 등록 폼 (최우선)**
```
SPEC.md 7장의 '업무 등록 30초 설계'를 그대로 구현해줘. 이건 이 앱에서 가장 중요한 화면이야.
- 보이는 입력은 업무명/카테고리/마감일 3개뿐. 담당자·시작일·산출물은 접힌 영역
- 업무명 필드 자동 포커스
- 카테고리: profiles.last_cat_* 기반 최근 사용 3개를 칩으로, 그 외는 '전체' 드롭다운
- 마감일: '이번주 금 / 다음주 금 / 이달 말 / 직접' 칩. 기본 선택은 이번주 금요일
- 중분류 선택 시 categories.ts TEMPLATES 로 체크포인트 자동 생성,
  산출물(deliverable)은 템플릿 마지막 항목으로 자동 설정
- 단축키: N(열기), Ctrl+Enter(저장 후 계속), Enter(저장), Esc(취소)
- '저장 후 계속' 은 카테고리·마감일 유지하고 업무명만 비움
- 저장 시 profiles.last_cat_l1/l2 갱신
- 중요도 필드는 만들지 마
```

**Step 5 — 내 업무 + 팀 현황**
```
'내 업무'와 '팀 현황' 화면을 구현해줘.
- 업무 행에서 체크포인트 토글 시 진척률·신호등 즉시 갱신
- 각 행에 복제(⧉) 버튼: 이름·카테고리·체크포인트 유지, 날짜만 다음 주기로 이동
- 마감일 수정 시 사유 입력 모달 필수, due_change_count 증가
- 팀 현황은 🔴 상단 고정, 담당자·카테고리·신호 필터
- 업무 행에서 바로 이슈 등록 가능
```

**Step 6 — 주간보고 + 엑셀 + 배포**
```
'주간보고': 이번 주 완료/진행중/차주계획을 자동 집계해 초안 생성,
사용자는 이슈와 코멘트만 입력 후 제출. 팀 통합본 탭 포함.

'리포트': SPEC.md 9장대로 SheetJS 로 4개 시트 엑셀 생성.
기간·담당자·신호 필터, 헤더 고정, 자동 필터, 신호 열 배경색, 열너비 자동조정.

.github/workflows/deploy.yml: main push 시 빌드 후 GitHub Pages 배포.
VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY 는 repository secrets 주입.
```
→ Settings > Pages > Source를 **GitHub Actions**로 변경
→ Settings > Secrets에 2개 값 등록

```markdown
# TaskBoard Lite

8명 팀 작업관리 도구. GitHub Pages 정적 배포 + Supabase.

업무 1건 등록에 30초를 넘기지 않는다.

계획진척률 = 경과일 기준 / 실적진척률 = 완료 체크포인트 비율
신호등: SV = 실적 - 계획. -5%p 이상 🟢, -20%p 이상 🟡, 미만 🔴
```
