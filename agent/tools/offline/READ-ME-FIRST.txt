================================================================================
 이슈 트래킹 에이전트 — 오프라인 꾸러미 (설치 불필요)
================================================================================

 인터넷도 pip 도 없는 윈도우에서 **압축만 풀어 실행**하는 꾸러미입니다.
 설치 프로그램을 돌리지 않고, 가상환경도 만들지 않고, 아무것도 시스템에
 등록하지 않습니다. 이 폴더를 지우면 흔적 없이 사라집니다.


--------------------------------------------------------------------------------
 0. 필요한 것 — 파이썬 하나뿐입니다
--------------------------------------------------------------------------------

 명령 프롬프트(cmd)를 열고 확인하세요:

     python --version

 3.10 / 3.11 / 3.12 / 3.13 / 3.14 중 하나가 나오면 그대로 진행하면 됩니다.
 다섯 버전 모두 이 꾸러미에 들어 있습니다.

 "찾을 수 없습니다" 가 나오면 아래도 해 보세요:

     py --version
     "C:\Program Files\Python312\python.exe" --version

 그래도 없으면 파이썬이 필요합니다. 설치가 안 되는 환경이라면
 python.org 의 **embeddable package**(zip, 설치 불필요)를 받아 이 폴더 안에
 풀어 쓸 수 있습니다. 담당자에게 문의하세요.

 아웃룩은 **실행해 두세요.** 꺼져 있으면 프로필 선택 창에서 멈춥니다.


--------------------------------------------------------------------------------
 1. 압축 풀기
--------------------------------------------------------------------------------

 아무 폴더에나 풉니다. 경로에 한글이나 공백이 있어도 됩니다.

     예) C:\ticket-agent\

 풀고 나면 이런 모양입니다:

     run.py            실행 진입점
     run-agent.bat     더블클릭용
     .env.example      설정 예시
     src\              소스
     lib\              라이브러리 (건드리지 마세요)
     READ-ME-FIRST.txt 이 파일


--------------------------------------------------------------------------------
 2. 설정 — 채울 값은 두 개뿐입니다
--------------------------------------------------------------------------------

 .env.example 을 복사해 .env 로 이름을 바꾸고 메모장으로 엽니다.
 (run-agent.bat 을 그냥 실행하면 이 과정을 대신 해 줍니다)

   SUPABASE_URL=https://dftqwkvhqjgwrfidsmwc.supabase.co

   SUPABASE_SERVICE_KEY=      <- Supabase 대시보드
                                 Project Settings > API keys > Secret key
                                 sb_secret_ 로 시작합니다.
                                 sb_publishable_ 는 웹용이라 안 됩니다.

   GEMINI_API_KEY=            <- 아래 설명을 보세요.

 GEMINI_API_KEY 는 **둘 중 아무 쪽이나 됩니다.**

   (가) 여기 .env 에 적는다        <- 설치할 때는 이게 간단합니다
   (나) 웹 설정 화면에 등록한다     <- 여러 PC 를 쓰거나 키를 자주 바꿀 때

 둘 다 있으면 웹 설정 화면이 이깁니다. 화면에서 바꿨는데 .env 가 이기면
 바꾼 줄 알고 옛 키를 계속 쓰게 되기 때문입니다. **한쪽만 있으면 그쪽을
 그냥 씁니다** — .env 에만 적어도 아무 문제 없습니다.

 (나) 를 고를 거라면 먼저 그 계정이 **관리자여야** 합니다. 가입 직후에는
 일반 사용자라 등록 버튼이 거부됩니다. Supabase SQL Editor 에서 한 번:

     update public.users set role = 'admin' where email = '내주소@회사.com';

 나머지는 그대로 둡니다. 특히:

   AGENT_MAIL_BACKEND=auto    <- 윈도우에서는 자동으로 outlook 이 됩니다.
   AGENT_SEND_MODE=display    <- 회신은 사람이 확인하고 보냅니다.
   OUTLOOK_FOLDER=받은 편지함/요청

 OUTLOOK_FOLDER 에 적은 폴더가 없다면 '받은 편지함' 으로 바꾸세요.
 하위 폴더는 / 로 구분합니다. 계정이 여러 개면 맨 앞에 계정 이름을 적습니다
 ('내주소@회사.com/받은 편지함/요청').

 ※ SUPABASE_SERVICE_KEY 는 권한 검사를 우회하는 키입니다.
    이 파일 밖으로 내보내지 마세요.


--------------------------------------------------------------------------------
 3. 실행
--------------------------------------------------------------------------------

 run-agent.bat 을 더블클릭하거나, 명령 프롬프트에서:

     cd C:\ticket-agent
     python run.py doctor        <- 점검 (먼저 이것부터)
     python run.py collect       <- 한 번만 수집
     python run.py run           <- 상시 실행

 doctor 가 이렇게 나오면 정상입니다:

     [i] Gemini 키 출처 - 설정 화면 (...)
     [O] Supabase - 연결 성공
     [O] 메일 백엔드 - '받은 편지함/요청' 접근 성공
     [O] Gemini API - 모델 'gemini-2.5-flash' 사용 가능

     ■ desk 수집 (경고만 — 여기가 실패해도 메일 수집은 그대로 돕니다)
     [O] desk 인증 - 쿠키 (설정 화면, ...) · 만료 2026-12-23 10:00 (29일 남음)
     [O] desk 연결 - 업무 N건
     [O] 수집 요청 표 - 대기·진행 0건
     [O] 대시보드 스냅샷 - 최신 2026-11-24 (0일 전)

 desk 줄은 경고(⚠️)여도 에이전트는 그대로 뜹니다. 6장을 보세요.

 처음에는 .env 의 SCAN_LIMIT 을 5 정도로 낮춰 몇 건만 돌려 보세요.


--------------------------------------------------------------------------------
 4. 자주 나오는 문제
--------------------------------------------------------------------------------

 "이 꾸러미에 파이썬 3.x 용 라이브러리가 없습니다"
   -> 담긴 것은 3.10~3.14 입니다. 더 새 버전이면 담당자에게 알려 주세요 —
      꾸러미를 다시 만들어야 합니다. 라이브러리를 갈아 끼워 쓸 수는 없습니다.
      급하면 이 PC 에 있는 다른 파이썬으로 실행해 보세요:
          py -3.12 run.py doctor

 "메일 백엔드 ❌"
   -> 폴더 이름이 다르거나, 아웃룩이 꺼져 있거나, 프로필 선택 창에서
      멈춰 있습니다. 아웃룩을 먼저 띄우고 메일이 보이는지 확인하세요.

 "Gemini 키 출처 - agent/.env"
   -> 오류가 아닙니다. .env 의 키를 쓰고 있다는 안내일 뿐이고 그대로 돌아갑니다.
      웹 설정 화면에 등록해 두고도 이 줄이 나온다면, 그때는 등록이 안 물린
      것이므로 화면에서 다시 확인하세요.

 "Gemini API 키가 없습니다"
   -> 어느 쪽에도 키가 없습니다. .env 의 GEMINI_API_KEY 에 적는 것이
      가장 빠릅니다 (2장 참고). 웹 설정 화면 쪽을 쓰려면 그 계정이
      관리자여야 합니다.

 수집은 되는데 티켓이 안 보임
   -> 웹의 '스크리닝' 화면을 보세요. 제외된 메일도 판정 근거가 남습니다.


--------------------------------------------------------------------------------
 5. 상시 실행 (작업 스케줄러)
--------------------------------------------------------------------------------

 ※ 반드시 "사용자가 로그온할 때만 실행" 을 고르세요.

    "로그온 여부에 관계없이 실행" 을 고르면 아웃룩 COM 을 쓸 수 없는
    세션에서 돌게 되고, 오류 없이 **아무 메일도 수집되지 않습니다.**

  1) 작업 스케줄러 > 작업 만들기
  2) 일반 > "사용자가 로그온할 때만 실행"
  3) 트리거 > 로그온할 때
  4) 동작 > 프로그램 시작
       프로그램:   C:\ticket-agent\run-agent.bat
       시작 위치:  C:\ticket-agent
  5) 조건 > "AC 전원이 켜져 있는 경우에만 시작" 해제


--------------------------------------------------------------------------------
 6. desk 수집 (0.5.0 부터) — 주간보고서용
--------------------------------------------------------------------------------

 run 으로 돌리면 메일 수집 옆에서 desk(업무 현황)도 읽어 대시보드에 올립니다.

   · 화면의 '주간보고서 생성' 이 넣는 수집 요청 — 10초마다 확인해 바로 받습니다
   · 정기 수집 — 월 18:00 · 화 09:00 (한국 시각). PC 가 꺼져 있었으면 켜질 때 한 번
   · 받은 스냅샷은 data\desk-snapshots\ 에도 남습니다. 대시보드에 못 올린 날짜는
     다음 수집 때 다시 올립니다. 이 폴더는 지우지 마세요

 desk 는 아이디·비밀번호 로그인이 없고(메일 인증), 사람이 브라우저로 로그인해
 받은 쿠키(CF_Authorization)로 읽습니다. 그 쿠키는 **대시보드 설정 화면 →
 desk 인증** 에 관리자가 붙여 넣습니다. 한 달쯤 가고, 만료 7일 전부터 대시보드
 위쪽에 배너가 뜹니다. 그때 새로 넣으면 됩니다.

   쿠키 복사: desk 에 로그인한 브라우저에서 F12 → Application(애플리케이션)
              → Cookies → desk 주소 → CF_Authorization 의 Value

 확인 명령:

     python run.py desk-scan --dry-run   <- 받아 보기만 (저장·업로드 안 함)
     python run.py desk-scan             <- 한 번 받아 대시보드에 올림

 desk 줄이 이렇게 나오면:

 "desk 인증이 없습니다"
   -> 대시보드 설정 → desk 인증 에 쿠키를 넣으세요. 1분 안에 반영됩니다.

 "desk 인증 만료" / "만료됐습니다"
   -> 브라우저로 desk 에 다시 로그인한 뒤 쿠키를 새로 복사해 넣으세요.

 "desk 연결 - 연결하지 못했습니다"
   -> 이 PC 에서 desk 주소가 막혀 있거나 프록시를 거쳐야 합니다. 브라우저로는
      열리는지 확인하고 담당자에게 알려 주세요.

 "수집 요청 표 - ... DB 에 없습니다 (25장)"
   -> 관리자가 Supabase SQL Editor 에서 supabase/schema.sql 을 다시 실행해야
      합니다. 그 전까지 화면의 수집 요청은 처리되지 않습니다 (정기 수집은 됩니다).

 desk 수집을 끄려면 .env 에 DESK_SCAN=off 를 적습니다.


--------------------------------------------------------------------------------
 7. 업데이트 — 소스만 바꾸기 (lib 는 그대로)
--------------------------------------------------------------------------------

 코드만 바뀐 업데이트는 ticket-agent-src-<버전>.zip 으로 옵니다 (수십 KB).
 라이브러리(lib\)는 안 바뀌었으니 다시 받을 필요가 없습니다.

  1) 에이전트 창을 닫습니다 (Ctrl+C 또는 창 닫기)
  2) 안내받은 릴리스 페이지에서 ticket-agent-src-<버전>.zip 을 받습니다
  3) zip 을 풀어 나온 **src 폴더만** 설치 폴더(예: C:\ticket-agent\)에 덮어씁니다
       - lib\ · .env · data\ 는 건드리지 않습니다
       - zip 의 .env.example 은 참고용입니다 (.env 와 이름이 달라 덮어쓰지 않습니다)
  4) run-agent.bat 을 실행합니다
       - doctor 첫 줄이 '에이전트 버전 : <버전>' 인지 확인
       - 0.5.0 부터는 '■ desk 수집' 줄이 더 나옵니다 (6장)

 0.5.0 으로 처음 올렸다면 마지막으로 하나 더:

  5) 대시보드 설정 → desk 인증 에 desk 쿠키를 붙여 넣습니다 (관리자)
     1분 안에 그 카드의 '에이전트가 쓰는 인증' 과 '마지막 수집' 이 바뀝니다.
